## 1. 道具系统定位（先讲清楚它是什么）

道具是 **Shanghai 配对消除的「决策辅助工具」**，不是数值养成、不是对战外挂。

**5 条设计原则**（不可破）：
1. **只服务消除自身**：道具效果仅限于当前消除局面，绝不给 AI 麻将任何优势（主文档 pillar 4 已锁；即使未来双游戏打通积分，道具也不跨游戏——机制不兼容）。
2. **不卖胜率，卖「少走弯路」**：提示/撤销/洗牌都是「帮你看得更清 / 回退一步」，不是「自动通关」。自动类道具（见 §8 扩展）严格限制为 P1 候选，MVP 不做。
3. **双通道并存**：每个道具都能「花积分买永久库存」或「看广告用一次」。广告是工具的另一种支付，不是「看广告得积分」。
4. **失败态才是高价值点位**：道具最大用量在死局与临死局，这是 IAA 转化最高效的时刻，设计要顺滑不羞辱。
5. **可审计、防刷**：道具发放/消耗走 append-only ledger，与积分同架构；广告发放必须 S2S 验签。

## 2. 核心道具清单（MVP 4 个）

| 道具 | 效果 | 触发时机 | 积分价 [PLACEHOLDER] | 广告替代 | 起始赠送 | 时机档 |
|------|------|------|------|------|------|------|
| **提示 Hint** | 高亮一对可配自由牌 | 主动，任何时候 | 200（最低，走量） | ✓（点位 7） | 3 | In-game |
| **撤销 Undo** | 回退上一次配对（恢复两张牌） | 主动，配对后立即可用 | 200 | ✓（点位 7） | 3 | In-game |
| **洗牌 Shuffle** | 剩余牌面重新随机分配，**保持全局可解** | 主动，任何时候 | 300 | ✓（点位 7） | 1 | In-game |
| **解围 Rescue** | 死局时强制洗出可解状态续命 | **被动**，仅 `availableMoves()==0 且牌未清完` | 500 | ✓（点位 6，每关 2 次） | 0 | End-game |

> 时机档沿用 Candy Crush 三档模型（Pre-game / In-game / End-game）。本玩法无步数/时间（主文档支柱 1），故无 Pre-game 步数类；可选「开局前带 1 次提示/洗牌」作为 A/B 实验，见 §14。

**定价相对关系**（具体值待 playtest，但层级锁定）：`提示 ≈ 撤销 < 洗牌 < 解围`。
理由链：提示最轻（只给信息）→ 撤销稍重（改变状态但精确恢复）→ 洗牌改变整盘（中）→ 解围是失败逃生口、决策压力最大（最高）。

## 3. 获取与库存模型（5 类渠道）

道具不只「买」，否则首日摩擦过高。获取渠道：

| # | 渠道 | 形式 | 说明 |
|---|------|------|------|
| 1 | **积分商城购买** | 永久入库 | 主通道，积分来自通关/星级/每日挑战（主文档 §5） |
| 2 | **看广告用一次** | 临时 session 令牌，不入库 | 点位 7，每关 3 次上限；前 3 session 受 cohort 广告纪律约束不弹 |
| 3 | **新手起始包** | 永久入库 | 首次进入赠送 提示×3 / 撤销×3 / 洗牌×1，降低首日摩擦 |
| 4 | **每日宝箱（点位 8）** | 看广告开，含积分+外观碎片，可含道具 | 每日 2 次，给「免费补给」节奏 |
| 5 | **赛季/内容奖励** | 永久入库 | 通关星级、读主题文章解锁（A5 内容→游戏奖励）、赛季图鉴合成 |
| 6 | **每日签到/任务/转盘** | 永久入库 | 每日签到分阶段送、每日任务活跃度达标送、幸运转盘抽；中文休闲头部（碰碰糖果/梦幻消消乐/糖果英雄）验证「零氪靠签到任务囤满道具」可压低付费压力，与广告克制纪律同源 |

**库存数据模型**（与 `points_ledger` 同架构，append-only）：
```
item_ledger(user_id, item_type, delta, reason, created_at)
库存余额 = SUM(delta) GROUP BY (user_id, item_type)
```
- `delta` 可正（发放）可负（消耗）；任何消耗必须先在服务端校验余额 ≥ 1，否则拒。
- 广告发放**不进 item_ledger**（临时令牌用完即焚），但记 `ad_reward_ledger` 流水（S2S 验签后落一条「已发放」，防同一次广告重复发）。
- 匿名用户库存存 cookie/localStorage，注册后并入（对齐任务清单 Phase 0）。

**解锁节奏（防信息过载，抄 Candy Crush 按进度解锁）**：MVP 不一次性全给——提示+撤销在前 3 关教学后立即可用（需求自然浮现）；洗牌在第 4–10 关引入（玩家已懂「堵死」概念）；解围在玩家**首次死局时**才引导弹出（最该出现的时刻才教）。这与难度平滑曲线（主文档 §4.3）同源：能力随进度给，不砸给新手，也是防「右偏悬崖」的软手段。

## 4. 双通道与广告纪律对齐

广告通道必须满足主文档 §7 的全部纪律：
- **首周 cohort 渐进**：前 3 次 session 近乎零广告（无论几天），道具的「看广告用一次」按钮在此期**只显示积分价、不弹广告**。
- **只绑工具**：提示/撤销/洗牌/解围天然是工具，合规。
- **频次红线**：道具广告 + 解围广告 + 宝箱广告共享全站下限 **8 次/日**，服务端二次校验（M2），超限按钮置灰。
- **信任框架**：每个广告按钮一句话明示换取物（"看一段短视频，免费得 1 次洗牌"），银发对不明 popup 警惕。

## 5. 消耗节奏与漏斗（玩家何时用哪个）

```
进入关卡
  ├─ 临场犹豫（"下一对该拆哪"）→ 提示（最轻，先消耗）
  ├─ 拆错顺序（"糟了这张不能先动"）→ 撤销（精确回退，仅次于提示）
  ├─ 自由牌枯竭（"都堵死了"）→ 洗牌（主动重排，改盘面）
  └─ 死局（availableMoves==0）→ 解围（被动逃生）或 认输重开
```

设计意图：
- **提示/撤销是高频低痛的「日常润滑」**，用量最大、定价最低，培养「道具 = 正常玩法的一部分」认知。
- **洗牌是中级救场**，比提示贵因为有副作用（打乱规划），应让玩家「宁愿先想想也不轻易洗」。
- **解围是兜底逃生**，只在真死局出现，配广告点位 6 转化。

**免费 Undo 每关 3 次（P0-D6）**：教学后自然消耗完，之后转积分/广告——这是付费意愿的第一道晴雨表（§7 指标 I4）。

## 6. 关键歧义修正：洗牌 ↔ 解围 边界

这是 §6 初稿没讲清、最易重复设计的点，明确如下：

| | 洗牌 Shuffle | 解围 Rescue |
|---|---|---|
| 触发 | 玩家主动，任何时刻 | 系统检测死局后被动弹窗 |
| 技术本质 | 对**剩余子局面**用生成器逆推法重洗成全局可解布局 | **同一套可解洗牌逻辑**，但只在死局态调用 |
| 价格 | 300 积分 / 看广告 | 500 积分 / 看广告（点位 6） |
| 撤销栈 | 洗牌后**清空**撤销栈（否则回溯到洗牌前的死局面矛盾） | 同洗牌，清空 |
| 复用 | `generator.shuffleSolvable(board, seed)` | 复用同一函数，仅触发条件不同 |

**结论**：引擎只实现一个「可解洗牌」原语 `shuffleSolvable`，UI 层分两个入口（主动按钮 / 死局弹窗）。解围不另写逻辑，只是「死局态下的洗牌 + 更高定价 + 绑定点位 6」。

## 7. 死局解围点位（IAA 转化核心）

死局 = 消除侧**广告转化效率最高的单一时刻**（主文档 §2 支柱 4：死局有台阶）。流程：

```
检测到 availableMoves()==0 且牌未清完
  → 弹死局弹窗（U6）：三选项
      ① 解围（500 积分）        — 有库存即走
      ② 看广告解围（点位 6）     — 每关 2 次，前 3 session 不弹广告版
      ③ 认输重开                — 不强制，保留尊严
  → 选①/②：调用 shuffleSolvable 重洗成可解 → 清空撤销栈 → 续玩
```

**为什么解围必须「可解」而非「随机」**：随机洗牌可能洗出另一个死局，玩家连续死局 = 流失。解围 = 保证续命成功，这是留存的底线（主文档 §2 支柱 2 的延伸）。

## 9. 健康指标与失败信号（道具专项）

继承主文档 §8，补充道具维度：

| 信号 | 定义 | 坏掉的意思 | 动作 |
|------|------|-----------|------|
| **I1** 道具使用分布 | Hint/Undo/Shuffle/Rescue 占比 | Rescue 占比 > 30% → 难度失控 | 回调生成器参数，非靠道具硬过 |
| **I2** 解围广告 CTR | 死局弹窗→看广告比例 | < 40%（信号 C）→ 玩家不知有路 / 时机错 | 优化弹窗文案/入口曝光 |
| **I3** 每关道具使用率 | 用 ≥1 道具的局占比 | > 50% 且通过率 < 40%（信号 B）→ 难度过头 | 调难度旋钮，不是加价 |
| **I4** 免费 Undo 用尽转化 | 免费 3 次用完后转积分/广告比例 | 接近 0 → 付费意愿弱 / 引导缺失 | 检查 HUD 道具栏曝光 |
| **I5** 广告 vs 积分通道比 | 道具使用里广告占比 | 广告通道占比骤降 → cohort 频率过紧或按钮隐蔽 | 调广告节奏 |
| **I6** 新手包消耗速度 | 起始包耗尽所需关数 | < 3 关耗尽 → 首日摩擦过高 | 加起始包 or 降前期难度 |

埋点（M3 已含）：每类道具的触发/消耗/来源（买/广告/赠送/宝箱）、死局率 + 解围转化、免费 Undo 余量。

## 10. 防滥用与公平性

- **服务端持有种子**（A1）：布局由服务端下发，客户端无法预知/篡改未解锁牌。
- **操作合法性校验**（A2）：撤销/洗牌若在客户端执行，结算时服务端校验「操作序列合法」（每步是合法配对或合法可解洗牌），伪造序列被拒。
- **广告 S2S 验签**（P0-E2）：`reward/verify` 回调验签后才记 `ad_reward_ledger`，伪造「看完了」被拒；同一次广告不重复发。
- **频次二次校验**（M2）：每关/每日道具广告上限服务端再卡一道，超限额按钮置灰不再弹。
- **余额校验**：任何消耗前服务端验 `item_ledger` 余额 ≥ 1，拒绝透支。

## 12. 排期（落在哪）

- **Sprint 1（引擎地基）**：E7 撤销栈 + E8 可解洗牌。因 generator（E6）已保证可解，洗牌直接复用其逆推原语，成本低；E11 道具接口同行。
- **Sprint 3（道具双通道）**：A3 + U4/U6 + 广告三点位 + 埋点（M3 含道具维度，day 0 即埋）。
- 免费 Undo×3（P0-D6）随 Sprint 3 的 U4 一并上线。

> 纪律重申：难度失控（信号 I1/I3）一律回调生成器参数，不靠玩家氪道具硬过——道具是「润滑」不是「难度补丁」。

## 14. 外部游戏道具设计参考与借鉴（活检 2026-08-14）

> 用户要求道具设计参考其他游戏思路。本轮活检 4 类样本：麻同类（行业锚）、三消标杆（Candy Crush）、家装类（Homescapes/Gardenscapes）、中文休闲消除（银发/休闲向，最贴近目标用户）。结论：我们的 4 道具模型被麻同类验证为行业标配；采纳触发时机三档、按进度解锁、免费福利矩阵、库存 caps 四项；明确不抄单格锤/棋盘合成 Power-up/步数体力道具/订阅无限道具。

### 14.1 参照样本
- **麻同类（标准锚）**：Microsoft Mahjong —— Hint（绿光跳动高亮一对）、Undo（撤消糖果可撤多步）、Shuffle（双箭头重洗一次）、每日挑战赚硬币+月度徽章。经典 Mahjong Solitaire 通用三件套 = Hint / Undo / Shuffle。
- **三消标杆**：Candy Crush Saga —— Boosters 三档触发：Pre-game（开局前带 Extra Moves/特殊糖）、In-game（随时 Lollipop Hammer 敲任意格 / Free Switch 交换任意两格）、End-game（失败时 Extra Moves×5）；免费靠 Events/Challenges/随机时刻 + Gold Bars 买；按关卡逐步解锁；库存 caps 限滥用。
- **家装类**：Homescapes / Gardenscapes —— 棋盘内 Power-up（Rocket/Bomb/Paper Plane/Rainbow Ball，靠大消除合成，机制特有）；外部 Booster（Hammer/Shovel 点任意格移除、Pre-level boosters 开局带）；「留到真卡关再用」策略哲学。
- **中文休闲消除（最贴近目标用户）**：碰碰糖果 / 梦幻消消乐 / 糖果英雄 / 天天消方块。共性：**免费福利极重**（签到/任务/转盘/宝箱/成就送道具）、**广告克制**（仅主动领福利时看视频，闯关不强制插播）、**零氪完整体验**、道具获取门槛低、无强制步数焦虑。

### 14.3 明确不抄（机制不兼容）
| 不抄项 | 原因 |
|--------|------|
