# 麻将 H5 · Next.js 15 App Router 原型开发任务清单

> 配套 `mahjong-iaa-design.md` v0.3。**v0.3 重大变化：砍掉玩家间实时对战，改为单人 vs 3 AI 陪玩**——架构大幅简化（无需实时传输），合规风险显著降低。假设消除形态为经典麻将连连看。

---

## 0. 关键架构判断（动手前必须拍板）

| 决策 | 选项 | 建议 & Rationale |
|------|------|------------------|
| **实时传输** | ~~Pusher/Ably~~ ｜ **不需要** | v0.3 砍掉 PvP，单人 vs 3 AI 全部服务端计算，客户端请求/响应即可。**Next Route Handler 完全够用，纯 Vercel 部署，零实时成本** |
| **部署** | Vercel（推荐） | 无长连需求，Vercel serverless 完美适配 |
| **数据库** | Postgres（Neon/Supabase）+ Drizzle ORM | 存账号/积分流水/对局结果/内容/AI 配置 |
| **对局状态** | 服务端内存 + Postgres 落盘 ｜ Redis(可选) | 单局在 Route Handler 内服务端权威推进，结束写 Postgres；Redis 仅用于限流/会话，非必需 |
| **鉴权** | Auth.js v5 + 匿名会话 | **匿名试玩是漏斗关键**：消除可匿名玩，注册后把匿名积分并入账号。必须支持 guest→user 合并 |
| **激励视频 SDK** | Google Ad Manager / AppLovin MAX web | 海外 web 激励视频首版二选一；**必须支持 S2S 回调验证**——客户端播完不算数，服务端收到广告网络回调才发积分（防刷） |
| **SEO 内容** | App Router Server Component + MDX | Next 的强项：内容页 SSG/ISR，generateMetadata 做 OG，文末嵌消除试玩组件 |

**一条不可妥协**：积分/下注/广告奖励**全部服务端权威**，客户端只做渲染与操作上报。客户端报"我赢了 1 万积分"直接忽略。

## 1. 推荐仓库结构（App Router）

```
app/
├─ (marketing)/               # SEO 内容群（公开、ISR）
│  ├─ page.ts                 # 首页 = 消除试玩落地
│  ├─ learn/page.ts           # "how to play mahjong" cornerstone
│  └─ solitaire-rules/page.ts
├─ (game)/
│  ├─ solitaire/page.ts       # 消除游戏（client 组件）
│  └─ mahjong/page.ts            # AI 陪玩对战（client，请求/响应，无实时）
├─ api/
│  ├─ auth/[...nextauth]/route.ts
│  ├─ wallet/route.ts         # 积分查询/流水
│  ├─ reward/verify/route.ts  # 广告 S2S 回调验签发分
│  ├─ mahjong/action/route.ts # 出牌操作上报（服务端权威推进 + AI 走牌）
│  └─ solitaire/level/route.ts # 关卡数据/结算
├─ content/                   # MDX 文章
lib/
├─ db/ (schema, drizzle)
├─ ai/ (AI 性格 + 难度 + 决策引擎)
├─ game/ (麻将规则引擎、消除关卡生成)
└─ ad/ (SDK 封装 + 回调验签)
```

## 2. 分阶段任务（按"先验证漏斗、再做核心"排序）

### Phase 0 · 脚手架（地基）
1. Next 15 + TS + Tailwind + Drizzle + Postgres 初始化；环境变量分层（dev/prod）。
2. Auth.js v5 接入，含**匿名会话**：首次访问发 guest cookie，注册时合并。
3. Postgres schema：`users / points_ledger（积分流水，只追加）/ games / tables / ad_rewards / content`。
4. Redis（可选）接入用于限流/会话；无实时层。
- **验收**：匿名访客拿到 guest_id，注册后 guest 数据并入；`points_ledger` 只追加、任何扣减走负向记录。
- **红线**：积分表绝不 UPDATE 余额，只 append 流水，余额 = SUM。审计与防刷的基础。

### Phase 1 · 积分钱包（消除独立闭环，双游戏打通降级为可选项）
5. `api/wallet` 查询余额（SUM 流水）；`api/reward/verify` 接收广告 S2S 回调，验签后 append 一条 `ad_reward` 流水。
6. 新客礼包、签到、每日任务的发放逻辑（服务端 cron 或登录时计算）。
7. 通胀监控脚本：日跑全服人均积分存量与周增速，>15% 告警（写日志/飞书）。**注**：v0.5 后此钱包为消除独立闭环服务；若未来 AI 麻将上线，复用同一 `api/wallet` 即可，不另建体系。
- **验收**：任意积分变动都有一条可追溯流水；伪造回调被拒；告警脚本能在测试库触发。
- **[PLACEHOLDER]**：新客 5,000、签到/任务额度待 A/B。

### Phase 2 · 麻将消除 MVP（获客漏斗 + IAA 主发动机，先做）
> 先做消除：无实时、无匹配、自带"卡关/失败"高意图广告时刻，是验证积分钱包 + IAA + SEO 落地的最快路径。
8. 消除关卡生成器（牌堆布局 + 可解性校验，保证每关有解）。
9. 消除核心玩法 client 组件：选牌→配对→消除→连击→通关；动画与音效（手感关键，反馈链 < 100ms）。
10. 道具系统：提示/撤销/洗牌/解围，**花积分买**（调 `api/wallet` 扣分）与**看广告得临时道具**（调 `api/reward/verify`）双通道。
11. 消除广告点位接入：卡关复活（每关2）、免费道具（每关3）、每日宝箱（每日2），全局 60s 冷却在 client 计时、服务端二次校验。
12. 落地页 `app/(marketing)/page.ts`：零注册即玩，匿名积分暂存 cookie，注册并入。
- **验收**：匿名能玩到通关；通关给积分入 wallet；卡关时激励视频弹出且完播后道具到账；伪造"我看完了"被服务端拒。
- **失败信号 D**：落地页跳出率 > 70% 先修落地，别加关卡。

### Phase 3 · AI 陪玩对战 MVP（留存核心，无实时）
> v0.3 简化：单人 vs 3 AI，全部服务端权威，客户端请求/响应。无匹配、无 Ably、无桌局广播。
13. 麻将规则引擎（`lib/game/mahjong`）：推倒胡，独立可单测——吃碰杠胡判定、番型计算、合法出牌校验。**服务端权威**。
14. AI 决策引擎（`lib/ai`）：性格（贪吃/保守/话痨）+ 难度（弱/中/强）分离；难度参数化以控胜率（见设计 4.1 RTP）。AI 走牌服务端计算。
15. 对局推进 `api/mahjong/action`：客户端上报出牌→服务端校验合法→推进 AI 三家走牌→返回新局面。一局在多次请求间推进，状态服务端持有。
16. 下注结算：玩家赢按底注×番型发分（受 RTP 监控）、输则底注回收、台费抽 5% append 流水；破产线触发救济广告；结算翻倍 + AI 出牌建议广告点位。
17. 胜率监控：每档位跑 Monte Carlo + 线上实际胜率对账，偏差 > 3pp 回调 AI 难度。
- **验收**：1 人 + 3 AI 完整跑通一局；客户端篡改操作被服务端拒；各档位胜率收敛到目标区间；抽水正确入流水。
- **[PLACEHOLDER]**：底注档、目标胜率、抽水 5% 待 playtest。

### Phase 4 · IAA 全面接入
19. 激励视频 SDK 封装（`lib/ad`）：统一播放接口 + S2S 回调验签；对战 5 点位（含 AI 出牌建议）+ 消除 3 点位接同一封装。
20. 广告纪律落地：局内零广告（对战摸打中禁弹）、全局 60s 冷却、人均 8-15 次/日上限（超限不再弹激励，防留存崩）。
21. 收入看板：DAU、人均曝光、完播率、eCPM、单日收入（按美元），与留存分桶对比。
- **验收**：7 个点位全部走 S2S 验签；超日均上限不再弹；看板能看"曝光 vs 7 日留存"曲线。

### Phase 5 · SEO 内容飞轮
22. MDX 内容管线：cornerstone 文章（how to play / rules / variants），ISR 缓存，generateMetadata + OG。
23. 文末嵌消除试玩组件（同 Phase 2 落地组件），内容流量直接转化试玩。
24. 内链 + 结构化数据（FAQ/HowTo schema）；sitemap、robots。
- **验收**：文章页 SSR 输出含可玩消除模块；Lighthouse SEO ≥ 90；搜索控制台可收录。

### Phase 6 · 增长闭环
25. 交叉导流：消除通关 3 次后弹"和 AI 牌搭子过两把？首登对战送 1,000 积分"入口，埋点转化率。
26. 每日任务/签到统一看板（双游戏任务合并）。
27. 周榜（好友/全球，纯荣誉无数值）、外观商城（牌背/桌布/消除皮肤，积分 sink）。
28. i18n（next-intl）：英文优先，预留中文/日文。
- **验收**：消除→对战转化埋点可看；外观购买扣分入流水；榜单不发放数值奖励。

## 3. 风险登记（提前暴露）

| 风险 | 影响 | 缓解 |
|------|------|------|
| AI 胜率漂移 | 对庄模型通胀/通缩失稳 | 每周 Monte Carlo + 线上实际胜率对账，偏差 > 3pp 回调难度 |
| 激励视频 S2S 回调丢失 | 玩家看了广告没到分，投诉 | 客户端兜底：超时未收回调可重放一次，仍以服务端为准 |
| 玩家误以为对手是真人 | 合规与口碑风险 | UI 明示"对手为 AI"，FAQ 说明 |
| 匿名→注册合并竞态 | 积分丢失 | 合并走事务 + 幂等键 |
| 海外 eCPM 低 | 回本慢 | 消除侧多点位拉曝光量；别靠插屏硬撑 |

## 4. 里程碑（建议节奏）

- **M1（消除+钱包+IAA）**：Phase 0/1/2/4 部分 → 能跑通"内容落地→消除试玩→看广告得道具→积分入账"。这是验证整个漏斗 + IAA 模型的最小闭环，**先上**。
- **M2（AI 陪玩核心）**：Phase 3 → 单人 vs 3 AI 能跑，留存信号 A + 经济信号 E 达标。
- **M3（增长闭环）**：Phase 5/6 → SEO 内容 + 交叉导流 + 外观商城。

下一步可以挑 M1/M2 里任一任务，我直接出代码骨架——推荐 `api/reward/verify`（S2S 验签）或 `lib/ai`（AI 决策引擎，控胜率的核心）。界面落地走 impeccable 视觉规范，避免泛 AI 审美。
