## 1. 设计基准与坐标系

### 1.1 桌面坐标系 = **970 × 710**（不是 980 × 720）

`components/games/HongKongTable.tsx` 的牌桌容器：

```
class="mahjong-desktop-board relative h-[720px] overflow-hidden border-[5px] border-[#032f22]"
```

Tailwind preflight 是 `box-sizing: border-box` → **720 含 5px 上下边框** → 内容高 **710**；宽同理，基准宽 980 减两侧边框 = **970**。

绝对定位的包含块是 padding box（此处无 padding）→ **所有 `top-[x%]` / `left-[x%]` 的分母是 970 / 710**。

🔴 **本文档所有坐标均以 970 × 710 为基准**。写实现时用相对单位（`top-[11.8%]`），⛔ 不硬编码像素。

### 1.2 牌尺寸（`components/games/TileFace.tsx`）

| size | 尺寸 | 用在哪 |
|---|---|---|
| `xs` | 40 × 24 | 竖屏暗牌 / 竖屏弃牌池 / 花牌 |
| `sm` | 36 × 28 | **横屏弃牌池** |
| `md` | 56 × 40 | 副露 / 竖屏花牌 |
| `lg` | 72 × 56 | 我的手牌 |
| `table` | 48 × 36 | （未用于桌面） |

### 1.3 暗牌（`app/globals.css` `.mahjong-standing-tile`）

- 单张 **40 宽 × 56 高**
- 横排（`--top`）步进：`margin-left: -3px` → **37px**；13 张 = 40 + 12×37 = **484px**
- 竖排（`--left/--right`）步进：`margin-top: -7px` → **49px**；13 张 = 56 + 12×49 = **644px**
- 第 14 张（`--drawn`）额外 `margin-left: .55rem` = 8.8px

### 1.4 缩放：`BoardScaleFrame` + `useBoardScale(980)`

`hooks/use-board-scale.ts` 是 `min(1, …)` —— **从不上采样**。视口 ≥ 980 时走 `scaled=false` 分支，容器 `width: 100%`。

🔴 **推论**：宽屏下牌桌被**横向拉伸** `(W−10)/970`（1280 视口 = 1.31×），而高度恒为 710。
→ **所有 `%` 定位的 x 值随视口伸缩，y 值不变**。这是 §3.5「横屏定死」的直接依据。

## 2. 【可执行】横屏 · 头像区（本轮定案）

### 2.1 决策

| 项 | 决定 |
|---|---|
| 头像尺寸 | **56 → 60 px** |
| 卡片形态 | **只对家**改横向（`flex-row`）；上家 / 下家 / 自己**保持纵向不动** |
| 对家让位 | 对家暗牌上移 8px；顶栏信息条上移 8px |

### 2.2 为什么「60px」与「只改对家」是自洽的

四条边的可用空间完全不同 —— **只有对家会因 60px 而装不下**，其余三家余量充足：

| seat | 约束（970 × 710） | 60px 后 |
|---|---|---|
| **3 对家** | 暗牌底 `88` → 弃牌池顶 `156.2` = **走廊 68.2px** | ❌ 卡高 68 > 68.2 → **需让 8px** |
| 2 上家 | 头像 x∈[20,116]；暗牌 x∈[145.5,185.5]；池 x 起 261.9 | ✅ 互不干涉，卡高 88→92 无影响 |
| 1 下家 | 与上家镜像 | ✅ 同上 |
| 0 自己 | `bottom-[16%]` **底边固定** → 加高只向上长 4px | ✅ 副露行在其**下方**，重叠深度不变 |

⚠️ **两条边界**：
- 60px 是**头像资产级**改动（`DefaultPlayerPortrait`），四家一起变；⛔ 不要写成「对家专属 60px」。
- 卡高变化只在**对家**造成问题（其余三家周围有富余）。⛔ 不要顺手改其他三家的定位。

## 3. 【可执行】横屏 · 其余改动

### 3.1 弃牌池：消除三家互压

**现状**（`components/games/table/DiscardPool.tsx`）：
- 容器 `absolute z-[5] w-[190px]`，网格 `grid grid-cols-6 gap-0.5`，牌 `size="sm"`（36×28），`slice(-18)`
- 6 列实际列宽 = (190−10)/6 = 30px < 牌宽 36px → 相邻牌重叠 4px，**视觉总宽 ≈ 196px**
- 满格 18 张 = 3 行 × 28 + 2×2 = **88px 高**

**四池位置与真实重叠**：

| seat | class | x 区间 | y 区间 |
|---|---|---|---|
| 3 对家 | `left-1/2 top-[22%] -translate-x-1/2` | `[390, 580]` | `[156.2, 244.2]` |
| 2 上家 | `left-[27%] top-[32%]` | `[261.9, 451.9]` | `[227.2, 315.2]` |
| 1 下家 | `right-[27%] top-[32%]` | `[518.1, 708.1]` | `[227.2, 315.2]` |
| 0 自己 | `bottom-[24%] left-1/2 -translate-x-1/2` | `[390, 580]` | `[451.6, 539.6]` |

🔴 **缺陷**：`对家 × 上家` 同时 **x 重叠 61.9px 且 y 重叠 17px** → 真实重叠矩形 **61.9 × 17px**。`对家 × 下家` 完全对称。
这正是「三家弃牌看着像一簇」的病因 —— **不是没分开，是分开了但横向压在一起**。

**目标**：四池形成「口」字方阵（每家从自己方位向中心推进），⛔ 中心留空。
**硬约束**：任意两池的**矩形交集必须为空**，且相邻池净间距 **≥ 8px**。
**次级约束**：弃牌池 ⛔ 不得压住对手暗牌（上家 x∈[145.5,185.5]、下家 x∈[784.5,824.5]）。

**建议值**（执行者可按约束微调）：
- 池宽 `w-[190px]` → **`w-[175px]`**，网格 `grid-cols-6` → **`grid-cols-4`**
  - 4 列 = 4×36 + 3×2 = 150 ≤ 175 ✅（不再挤压牌面）
  - 满格 18 张 = 5 行 × 28 + 4×2 = **148px 高**（比现状高 60px，需重新校验纵向）
- `seat 2` `left-[27%]` → **`left-[20%]`**（x∈[194, 369]）
- `seat 1` `right-[27%]` → **`right-[20%]`**（x∈[601, 776]）
- `seat 3` / `seat 0` 保持居中 → 新 x∈[397.5, 572.5]

**校验**（按新值）：
| 对 | x 间隔 | y 间隔 |
|---|---|---|
| 3 ↔ 2 | 28.5px | 17px 重叠但 x 已分离 → **交集为空** ✅ |
| 3 ↔ 1 | 28.5px | 同上 ✅ |
| 2 ↔ 暗牌 | 8.5px | — ✅ |
| 1 ↔ 暗牌 | 8.5px | — ✅ |
| 0 ↔ 3 | 同一列 | y 间隔 29.4px ✅ |

⚠️ 高度变 148px 后**必须重新校验**：`3 × 0`（156.2+148=304.2 vs 451.6 → 间隔 147.4 ✅）、`2/1 × 0`（375.2 vs 451.6 → 76.4 ✅）。
⚠️ 若 148px 与 `McrScoreCoach`（`right-[12%] top-[56%]` → y 起 397.6）冲突，优先**下移池顶**而非缩容量。

### 3.5 横屏定死：补 `max-width`

**问题**：`useBoardScale(980)` 是 `min(1, …)`，宽屏走 `scaled=false` → 容器 `width:100%` → 牌桌横向拉伸，`%` 定位失真（1280 视口 1.31×）。

**决定**：给桌面容器**额外锁一个最大宽度**，超出部分左右留白居中。

```diff

+ className="mahjong-desktop-board mahjong-desktop-board--seasonal relative mx-auto h-[720px] max-w-[970px] overflow-hidden …"
```

⚠️ **备选**（二选一，⛔ 不要同时做）：把 `useBoardScale` 的上限从 `1` 放宽到 ~1.3，让牌桌在宽屏**等比放大**而非拉伸。优点是填满屏幕，缺点是影响所有使用该 hook 的页面，回归面大。**默认走 `max-w` 方案。**

### 5.1 竖屏设计基准

| 项 | 值 | 来源 |
|---|---|---|
| 逻辑视口 | **390 × 844**（iPhone 14）；测试下限 **320 × 568** | — |
| 外层 | `h-[calc(100dvh-7rem)] min-h-[520px]`（7rem = 112px） | `MobileMahjongTable.tsx` 根节点 |
| 工具条 | `min-h-11` = **44px**（现状 390px 下 `flex-wrap` 折行 → 实测 **85px**） | 同上 |
| **牌桌区 H** | `视口 − 112 − 44` → iPhone 14 = **688**；iPhone SE3（667）= **476** | 实测 |
| 🔴 铁律 | **H 在 476–820 之间浮动 → ⛔ 不得用固定 px 撑骨架**（现状的 `top-[x%]` 骨架即因违反此条而溢出错位） | 实测 |

**牌尺寸（竖屏所有 `TileFace` 都传 `traditional` → 走 `TILE_ART_SIZE`，不是 `SIZE_CLASS`）**

| size | 高 × 宽 | 用途 |
|---|---|---|
| `xs` | 40 × **28.64** | 手牌 / 弃牌池 / 花牌 |
| `sm` | 36 × 25.76 | 副露 |

### 5.3 决策 1 · 侧暗牌 = 横排 5 张 + `×N`

- 竖排 14 张 448px → **横排 5 张 = 100 × 44**（实测，`-ml-1`）＋ 右上角计数徽标（23.6 × 16）。
- 保留「手牌变短」的视觉信号（副露后 `count` 变小），同时把 404px 还给别处。
- ⛔ 不改成「1 张牌背」——会丢掉手牌长度的直观；⛔ 不改「横向短条铺桌心」——与「四方围坐」冲突。

### 5.4 决策 2 · 弃牌池 = 全部 18 张，列数按位置分开定

`slice(-9)` → **`slice(-18)`**（与横屏 `DiscardPool` 对齐）。列数不能统一，因为三个位置的可用宽高不同：

| 对家池 | **6 列 × 3 行** | 180.8 × 138 | 纵向最紧（上方是暗牌、下方是自己池），只能压行数 |
| 自己池 | **4 列 × 5 行** | 121.5 × 228 | 居中，宽高都还有余量 |

### 5.6 短屏降级规则（**H < 600 强制生效**）

468–688 的浮动意味着「18 张」在矮屏必然装不下（SE3 只有 476）。**降级只允许这一种方式**：

- 三类弃牌池的容器改为 **`max-h-full overflow-y-auto`**，父容器 `flex-1 min-h-0`；
- 内容顺序**保持时间序**（上→下），矮屏自动只露出最新若干行，**可手动上滑看早巡**；
- **保底 2 行**（88px）——少于 2 行则提前把「侧 pill + 牌背条」折叠成单个 pill（省 44px）；
- ⛔ **不许**用「减少张数」降级（那正是 09-23 要修的问题）；
- ⛔ **不许**给牌加 `scale` 缩放（会破坏牌面可读性）。
